# SG90 舵机互斥锁多任务实验

基于 OpenHarmony LiteOS-M 与 Hi3861 开发板的 SG90 舵机控制示例。

本实验创建三个**相同优先级**的任务，通过互斥锁保护 SG90 舵机这一共享资源，并使用信号量保证任务按指定顺序执行。

## 实验效果

程序运行一次后，串口输出及舵机动作如下：

| 顺序 | 任务 | 串口输出次数 | 舵机动作 |
| --- | --- | ---: | --- |
| 1 | 任务 1 | 1 次 `任务1开始运行` | 左转 45° |
| 2 | 等待 | 约 3 秒 | 保持当前状态 |
| 3 | 任务 3 | 2 次 `任务3开始运行` | 右转 45° |
| 4 | 任务 2 | 3 次 `任务2开始运行` | 回到中间位置 |

## 任务同步说明

- 三个任务的优先级均为 `25`。
- `servo_mutex` 是互斥锁，用于确保任意时刻仅有一个任务操作舵机。
- `task3_start_sem` 由任务 1 在运行约 3 秒后释放，允许任务 3 开始。
- `task2_start_sem` 由任务 3 完成后释放，允许任务 2 立即开始。

> 互斥锁只能保护共享资源，不能可靠地规定同优先级任务的执行顺序；因此本示例额外使用信号量完成顺序控制。

## 构建配置

将 `SG90.c` 和 `BUILD.gn` 放入 OpenHarmony 工程的：

```text
applications/sample/wifi-iot/app/3.0_SG90_Mutex/
```

在 app 目录的 `BUILD.gn` 的 `features` 中加入：

```gn
"3.0_SG90_Mutex:SG90",
```

所需头文件目录配置已包含在本项目的 `BUILD.gn` 中。

## 编译与烧录

1. 在 VS Code 远程环境中编译工程。
2. 找到生成的固件文件，通常为：

   ```text
   out/wifiiot/Hi3861_wifiiot_app_allinone.bin
   ```

3. 使用 HiBurn 选择该 `.bin` 文件。
4. 选择开发板对应的 COM 口，点击 **Connect**。
5. 出现 `Connecting...` 后按开发板的 **RESET** 键。
6. 看到 `Execution Successful` 后点击 **Disconnect**，再按一次 RESET 启动程序。

## 串口查看

烧录完成后，使用串口调试助手打开开发板对应的 COM 口，波特率设置为 `115200`。

若串口输出中文乱码，请将串口工具的编码改为 UTF-8。

## 常见问题

### 舵机左右方向相反

不同安装方向下，左、右会相反。可交换 `engine_run_45()` 与 `engine_run_135()` 中的脉宽：

- `1000 us`：约 45°
- `1500 us`：中间位置（约 90°）
- `2000 us`：约 135°

### HiBurn 一直显示 `Connecting...`

确认选择的是开发板对应的 COM 口，关闭其他占用串口的软件，将串口切换到 3861 端，然后按开发板 RESET 键进入烧录模式。
